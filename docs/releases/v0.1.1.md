This release fixes Antigravity sessions, which could read files but not change anything.

## Fixed

- **Antigravity can edit files, run commands and ask questions again.** Agmen starts Antigravity as an `agmen` agent, and since agy 1.5 an agent that names no tools gets a read-only set. The agent now names the tools agy's default agent has. Restart your Antigravity tabs after updating; the fix arrives when a tab starts.
- **A session without Agmen's tools says so.** A Kimi Code or Antigravity session that starts while its agent isn't connected to this copy of Agmen shows **No Agmen tools** on its card, also after a restore. Before, Agmen offered Connect once and then the session looked like any other.
- **An Antigravity question shows as waiting.** When Antigravity asks you something with its `ask_question` tool, the dot on its card turns blue, and Agmen alerts you if you're looking elsewhere. Before, it looked busy.
- **A parent hears when a waiting turn is cancelled.** A turn that ended while it waited on you, because you cancelled it or dismissed its question, never reported to its parent.

## Added

- **A fallback for Antigravity.** agy won't run an agent that names a tool it doesn't have. If a later agy drops one of the tools Agmen names, a new Antigravity session starts again as agy's default agent, with its first task.

## Update

Run the install command again:

```powershell
irm https://github.com/cxbxmxcx/agmen/releases/latest/download/install.ps1 -OutFile "$env:TEMP\agmen-install.ps1"; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\agmen-install.ps1"
```

Or download `Agmen-win-x64.zip` below and extract it over the old folder, after you exit Agmen from its tray icon.
